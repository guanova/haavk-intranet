# 08 · 资料征集功能（投稿 + 审核 + WebDAV 转存）

> 2026-10-26 上线。寻人启事页整体替换为「资料征集」页（#/collect，旧 #/wanted 自动跳转）。

## 用户侧

- **匿名可投稿**：称呼（必填，用于鸣谢墙署名）、联系方式（选填，仅管理员可见）、资料类型（六类：活动截图/设定资料/帖子文案/高清素材/捉虫纠错/其他）、说明文字、图片（PNG/JPG/WEBP，多选，单张 ≤5MB，服务端魔数嗅探）。
- 文字与图片至少填一项；非法类型静默归为「其他」。
- **限流**：按 IP 每 3600s 最多 5 次（含校验失败的请求），超限 429。
- **鸣谢墙**：页面下方「已收录档案」公开列出已收录投稿（称呼+类型+说明，不含联系方式与附件）。
- 登录用户投稿自动带工号身份；游客投稿旁有注册引导。

## 管理侧（管理面板「征集」tab）

- 顶部 WebDAV 状态条（待转存/已转存/失败计数；未启用时给出配置引导）。
- 筛选（待收录/已收录/不收录）+ 表格（称呼/类型/说明/图片缩略图/身份/时间/状态/操作）。
- 收录：可填备注与**奖励点数**（0–5000，仅投稿者是在册员工时入账，走 `points.addPoints` 统一流水，对账不破）。
- 不收录：**必须填理由**（后端 400 强制）。
- 重复审核被拒（409）；奖励点数落库 `submissions.reward_points`（migration 004）。
- 附件仅管理员可读（`/media/submissions/:name` 需管理员会话；路径穿越被 basename+正则白名单拦截）。

## WebDAV 转存

- 配置：管理面板 → 站点配置 → webdav 组（enabled/url/user/pass，editable=1；`publicSettings` 不下发）。
- 机制：worker 每 20s 扫 `submission_files` 的 pending/failed（attempts<8）→ MKCOL 逐级建目录 → PUT 到 `{base}{YYYY-MM}/{submissionId}/{storedName}`。
- 未配置时不动（保持 pending，配置好后自动补传）；失败标 failed 可在 tab 里一键重试（支持按投稿限定）。
- 附件本体始终先落本地 `data/uploads/submissions/`，WebDAV 是镜像层。

## 数据与端点

- 表：`submissions`（status pending/approved/rejected、reward_points）、`submission_files`（webdav_status pending/ok/failed/skipped、attempts）。
- 端点：`POST /api/submissions`（multipart）、`GET /api/submissions/credits`（公开）、`GET /api/admin/submissions`、`POST /api/admin/submissions/:id/review`、`POST .../webdav/retry`、`POST .../webdav/test`、`GET .../webdav/stats`、`GET /media/submissions/:name`（管理员）。
- 审计：`submission.create` / `submission.review`（含 action/note/reward）均落 `audit_logs`。
