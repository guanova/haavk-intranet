# 部署与运维说明

> 目标读者：负责上线与日常运维的工程师。
> 本项目**零 npm 依赖**，唯一的运行时要求是 **Node.js ≥ 22.5**（内置 `node:sqlite`）。

---

## 一、环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| Node.js | **≥ 22.5**（推荐 24 LTS 或更高） | 依赖内置 `node:sqlite` 模块 |
| 操作系统 | Windows / Linux / macOS | 已在 Windows + Node 24.21 实测 |
| 磁盘 | ≥ 200MB | SQLite 库 + 头像文件；按用户量增长 |
| 内存 | ≥ 256MB | 单进程，SQLite 为本地文件库 |
| 网络 | 单端口对外（默认 8137） | 无需 Redis / MySQL 等外部服务 |

验证 Node 版本：

```bash
node -v
node -e "require('node:sqlite'); console.log('node:sqlite OK')"
```

## 二、首次部署

```bash
# 1. 取得代码
cd haavk-intranet

# 2. （可选）设置初始密码与端口
export PORT=8137                              # Windows: set PORT=8137
export HAAVK_ADMIN_PASSWORD='你的管理员密码'      # 不设置则随机生成并打印一次
export HAAVK_OFFICER_PASSWORD='AI高管初始密码'    # 同上

# 3. 启动（首次启动会自动建库、执行迁移、播种出厂数据）
node server/index.js
```

启动日志会输出：

```
[db] <项目>/data/haavk.db
[db] schema v1
[seed] 部门 17 · 岗位 5 · 板块 7 · 管理员 1 · AI 高管 4 · 配置项 14

  哈夫克内网  http://127.0.0.1:8137/
  管理面板     http://127.0.0.1:8137/#/admin
```

Windows 用户可直接双击 **`start.cmd`**（会检查 Node 版本并带上默认密码启动）。

### 上线前必做三件事

1. **登录管理面板修改初始密码**：`webops_admin` 是唯一出厂管理员账号，**不开放注册**。
2. **填写备案信息**：管理面板 → 站点配置 → 备案信息（ICP / 公安备案 / 主办单位 / 版权声明）。留空则页脚不渲染该行，不会出现 null/undefined。
3. **调整点数与 @ 风控规则**（如运营策略与默认不同）：管理面板 → 站点配置 → 点数 / @ 风控。
   出厂值为需求硬性值：**每日 500 / 发帖 50 / 回复 100**，@ 冷却 60 秒、每小时 5 次、单帖最多 3 位。

### 演示数据（可选）

面向首次上线、尚无真实用户时，让站点有可浏览的初始内容：

```bash
node server/tools/demo-seed.js     # 15 位演示员工 + 16 篇帖子 + AI 高管发言 + 1 条已通过的 @ 审核
node server/tools/avatar-seed.js   # 用纯 Node 生成并登记头像（走真实 uploads 路径）
```

演示员工统一密码 `Haavk#2026`（示例账号：`claire` / `lina` / `panshi`）。

> 生产环境请**不要**保留演示数据，或上线后在管理面板逐条清理。可用 `node server/tools/reset.js --yes` 清空全部业务数据并重新播种。

## 三、环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` / `HAAVK_PORT` | `8137` | 监听端口 |
| `HAAVK_HOST` | `0.0.0.0` | 监听地址；仅本机可设为 `127.0.0.1` |
| `HAAVK_DB` | `<cwd>/data/haavk.db` | SQLite 文件路径（**建议挂载到持久卷**） |
| `HAAVK_UPLOAD_DIR` | `<cwd>/data/uploads/avatars` | 头像文件目录（**建议与数据库同卷**） |
| `HAAVK_ADMIN_PASSWORD` | 随机生成 | 仅首次创建 `webops_admin` 时使用 |
| `HAAVK_OFFICER_PASSWORD` | 随机生成 | 仅首次创建 AI 高管账号时使用 |
| `HAAVK_COOKIE_SECURE` | 关闭 | 置 `1` 时 Cookie 带 `Secure`（**HTTPS 部署必须开启**） |
| `HAAVK_TRUST_PROXY` | 关闭 | 置 `1` 时信任 `X-Forwarded-For`（反代后才可开启，否则限流可被伪造头绕过） |

## 四、反向代理（推荐 Nginx）

```nginx
server {
    listen 443 ssl http2;
    server_name your-domain.example;

    ssl_certificate     /etc/letsencrypt/live/your-domain.example/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.example/privkey.pem;

    # 头像上传最大 2MB，留出 multipart 开销
    client_max_body_size 4m;

    location / {
        proxy_pass         http://127.0.0.1:8137;
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }
}
```

生产环境同时设置：

```bash
export HAAVK_COOKIE_SECURE=1
export HAAVK_TRUST_PROXY=1
```

## 五、进程守护

### systemd（Linux）

`/etc/systemd/system/haavk.service`：

```ini
[Unit]
Description=Haavk Intranet
After=network.target

[Service]
Type=simple
User=haavk
WorkingDirectory=/opt/haavk-intranet
Environment=PORT=8137
Environment=HAAVK_COOKIE_SECURE=1
Environment=HAAVK_TRUST_PROXY=1
ExecStart=/usr/bin/node server/index.js
Restart=always
RestartSec=3
# SQLite 需要可写目录
ReadWritePaths=/opt/haavk-intranet/data

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now haavk
sudo journalctl -u haavk -f
```

### Windows

`nssm install HaavkIntranet "C:\Program Files\nodejs\node.exe" "server\index.js"`，或在任务计划程序中配置"计算机启动时"运行 `start.cmd`。

## 六、备份与恢复

需要备份的只有两项：

```
data/haavk.db            # SQLite 数据库（WAL 模式下同时存在 -wal / -shm）
data/uploads/avatars/    # 头像文件
```

**热备份（推荐，不中断服务）**：

```bash
sqlite3 data/haavk.db ".backup 'backup/haavk-$(date +%F).db'"
tar czf backup/avatars-$(date +%F).tgz data/uploads/avatars
```

> 直接 `cp` 正在被写入的 WAL 库可能拿到不一致快照，务必使用 `.backup` 或先停服。

**恢复**：停止服务 → 覆盖 `data/haavk.db` 与 `data/uploads/` → 启动服务 → 跑一次对账：

```bash
node server/tools/reconcile.js
```

## 七、日常运维命令

```bash
node server/tools/migrate.js          # 只跑迁移（不启动 HTTP 服务）
node server/tools/seed.js             # 补齐出厂数据（幂等，不覆盖已有值）
node server/tools/reconcile.js        # 对账：流水 vs 余额、重复领取、回复计数
node server/tools/reconcile.js --fix  # 按流水修正余额
node server/tools/reset.js --yes      # 清空业务数据并重新播种（危险）
node server/tools/smoke.js            # 接口冒烟自检（临时库，不影响线上）
node tests/server/e2e.js              # 端到端验收自检（临时库 + 随机端口）
```

**对账脚本必须长期保持 0 差异**。出现差异时不要手动改库，先查看 `points_ledger` 定位原因。

## 九、常见问题

**Q：`ERR_UNKNOWN_BUILTIN_MODULE: node:sqlite`**
A：Node 版本过低。升级到 ≥ 22.5（推荐 24 LTS）。

**Q：端口被占用**
A：`PORT=8188 node server/index.js`，或先停掉占用进程。启动脚本也会明确报 `EADDRINUSE`。

**Q：头像上传返回 415**
A：服务端用**文件魔数**判定图片类型，不信任客户端 `Content-Type`。请使用真实 PNG/JPG/WEBP 文件。

**Q：头像上传返回 413**
A：单张上限 2MB。前端上传前会预检并提示。

**Q：页面显示"无法连接服务器"**
A：静态页面可以单独打开，但数据全部来自服务端。请确认服务已启动，并通过 `http://127.0.0.1:8137/` 而非 `file://` 访问。

**Q：`@` 呼叫一直停留在"审核中"**
A：审核由后台 worker 推进（间隔 2.5 秒，单条通常在 3–10 秒内结案）。若长时间不结案，会由 `sweepStaleMentions` 在 10 分钟后按"未通过"结案。可用 `node server/tools/smoke.js` 验证审核链路是否正常。

**Q：当天点数领不到**
A：每日只能领取一次，由 `daily_claims` 表的 `UNIQUE(user_id, claim_date)` 硬约束保证。重复领取返回 409。
