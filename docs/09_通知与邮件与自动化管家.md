## 一、通知板块（站内公告）

用的位置：前台 `#/notifications`（顶栏「通知」入口）、后台「管理面板 → 通知」。

### 字段与状态

| 字段 | 说明 |
| --- | --- |
| `title` | 标题，≤120 字 |
| `summary` | 摘要；留空时自动截取正文前 80 字 |
| `body` | 正文，≤20000 字，空行分段 |
| `level` | `normal` 通知 / `important` 重要通知 / `urgent` 紧急通知（只影响标签样式与邮件标题前缀） |
| `status` | `draft` 草稿 / `published` 已发布 |
| `is_pinned` | 置顶，列表排在前面 |
| `publish_at` | 发布时间；`publish_at > now` 的条目对外不可见（可预先排期） |
| `email_state` | `none` 未推送 / `sending` / `sent` / `failed` |
| `email_total/ok/fail` | 最近一次推送的计数 |

### 前台行为

- 只显示 `status = 'published'` 且 `publish_at <= 当前时间` 的条目。
- 置顶优先，其余按发布时间倒序；一次取 50 条。
- 列表默认只显示标题、作者、时间、摘要；点「查看全文」展开正文，再点收起。
- 无条目时显示「暂无通知」，接口失败显示错误块（不静默空白）。

### 后台行为

- 新建 / 编辑（标题、摘要、级别、正文、置顶）。
- 「发布」把草稿置为 `published`（**不发邮件**）；邮件是独立的一步。
- 「推送」向所有订阅邮箱逐封发送；草稿状态不允许推送。
- 「记录」查看该通知的逐封发送记录（地址、成功/失败、错误原因）。
- 删除为物理删除，仅限通知本身，`mail_log` 保留。

## 二、SMTP 邮件推送

### 配置位置

管理面板 → 站点配置 → 「邮件推送（SMTP）」分组。配置键存在 `site_settings`（`group = mail`），`ensureSeeded()` 幂等补齐，**老库升级后自动出现**。

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `mail.enabled` | `0` | 总开关；为 0 时「推送」按钮会拒绝执行 |
| `mail.host` | 空 | SMTP 主机，如 `smtp.qq.com` |
| `mail.port` | `465` | 465 = 加密直连（推荐）；587 = STARTTLS |
| `mail.secure` | `1` | 1 = 隐式 TLS；0 = 明文连接（587 由 STARTTLS 自动升级） |
| `mail.user` | 空 | 登录账号 |
| `mail.pass` | 空 | **授权码**（QQ/163 邮箱不是登录密码） |
| `mail.from` | 空 | 发件人地址，通常与 `mail.user` 相同 |
| `mail.site_url` | 空 | 邮件正文里的回链域名，如 `http://154.89.149.92` |

填完在「通知」页点「测试连接」（`POST /api/admin/mail/test`），返回 `ok` 才算通。

### 实现（零依赖）

`server/lib/smtp.js` 用 `node:net` / `node:tls` 手写最小 SMTP 客户端，不引入 nodemailer：

- 多行响应（`250-…` / `250 …`）逐行读取；
- 隐式 TLS（465）与 STARTTLS 升级（587）都支持；
- AUTH 优先 `PLAIN`，服务器不支持时退 `LOGIN`；
- 中文标题按 RFC 2047 `=?UTF-8?B?…?=` 编码，正文 base64 折行，避免乱码；
- `rejectUnauthorized: false`，容忍自签证书（企业内网常见）。

`server/lib/mailer.js` 负责业务层：

- `subscriberEmails()`：只取 `email_opt = 1`、邮箱非空、账号未停用的用户，小写去重、正则过滤非法值；
- `pushNotification(id)`：**串行**逐封发送（避免被 SMTP 判为并发刷信），每封写一条 `mail_log`，最后回写 `email_state` 与计数；
- `composeNotificationMail()`：标题前缀按级别加【通知】【重要通知】【紧急通知】，附摘要、正文、回链和署名。

### 订阅入口

个人资料页「编辑资料」里有「邮箱（用于接收集团通知）」输入框 + 「重要通知发送到此邮箱」勾选。走 `PATCH /api/me/email`，与昵称/签名分开保存（一个字段失败不会拖垮整张表单）。邮箱不对外展示。

## 三、自动化管家（机器可调用的管理接口）

给脚本 / AI 用的**可撤销**机器身份，权限等同其所有者（必须是站点管理员）。

### 令牌

- 明文形如 `hk_` + 48 位十六进制，**只在创建时显示一次**，库中只存 `sha256`。
- 表 `api_tokens`：`name / token_hash / owner_id / scope / use_count / last_used_at / revoked_at`。
- 请求头 `x-agent-token: hk_...`；`currentUser()` 在无 Cookie 时自动回退到令牌身份，因此**所有管理接口都能用令牌调用**。
- 安全约束：令牌不能创建令牌、不能吊销令牌（只能由人用管理员会话操作）；所有者被停用或非管理员时令牌立即失效。

### 命令行管理

```bash
node server/tools/agent-token.js list
node server/tools/agent-token.js create --name "lead-agent" --owner webops_admin
node server/tools/agent-token.js revoke --id 3
```

### 专用接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/agent/ping` | 连通性 + 当前身份（`via: agent-token / session`） |
| GET | `/api/agent/summary` | 全站体检：用户/论坛/通知/征集/邮件的计数 + 最近 5 帖 |
| GET | `/api/agent/tokens` | 列出令牌（仅管理员会话） |
| POST | `/api/agent/tokens` | 新建令牌（仅管理员会话） |
| POST | `/api/agent/tokens/:id/revoke` | 吊销（仅管理员会话） |

```bash
curl -H "x-agent-token: hk_xxx" http://127.0.0.1:8137/api/agent/summary
```

除上表外，`/api/admin/*` 全部可用令牌调用，例如：

```bash
# 发一条通知并推送邮件
curl -X POST -H "x-agent-token: hk_xxx" -H "content-type: application/json" \
  -d '{"title":"标题","body":"正文","level":"important","publish":true,"pushMail":true}' \
  http://127.0.0.1:8137/api/admin/notifications
```
